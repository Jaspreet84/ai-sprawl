# Roadmap

## Phase 1: Define the control point

Goal: prove that AI-amplified sprawl can be detected early in pull requests.

- GitHub app installation flow
- basic PR ingestion
- risk scoring for obvious signals
- lightweight review feedback

## Phase 2: Make it trustworthy

Goal: make the product useful enough that teams keep it on.

- reduce false positives
- add ownership checks
- improve weekly reporting
- track repo-level patterns over time

## Phase 3: Expand the control surface

Goal: move beyond PRs into broader software governance.

- scripts and automations inventory
- agent and dependency visibility
- secret and permission review
- cleanup recommendations

## Phase 4: Enterprise hardening

Goal: make it ready for larger teams with compliance and admin needs.

- audit trail
- policy configuration
- SSO and org controls
- reporting for security and platform teams
